# 08 — Risques résiduels, limites et éléments hors code

> **Statut de déploiement (3 nov. 2026)** : correctifs **testés en local, non déployés** sur https://symoprint.com (autorisation en attente).

Rien n'est « 100 % sécurisé ». Ce registre liste ce qui n'est **pas** réglé ou **pas vérifiable** depuis le code. « À vérifier » = non confirmé ; « Config externe » = dépend de l'hébergeur, du DNS, d'un prestataire ou d'une décision du propriétaire.

| ID | Sév. | Risque | Pourquoi il subsiste | Atténuation actuelle | Action / responsable | État |
|---|---|---|---|---|---|---|
| **R-00** | **Critique** | **Les 19 constats de `02` restent ouverts en production** | Correctifs non déployés (autorisation requise) | Sauvegarde quotidienne créée ; sauvegarde pré-migration réalisée | Autoriser le déploiement (procédure `10` §A) | **À faire** |
| R-01 | Élevée | **Délivrabilité des e-mails** : confirmation de compte, réinitialisation de mot de passe et alertes peuvent ne pas arriver | DNS : SPF = `include:_spf.reach.hostinger.com ~all` (couvre Hostinger Reach, pas forcément l'envoi du serveur), DKIM Reach seulement, **DMARC `p=none`**, **aucun MX** ; adresse de contact des e-mails (`contact@symoprint.fr`) sur un autre domaine | **Pilote SMTP authentifié codé et testé** (`mail_driver: 'smtp'`) ; achat sans compte toujours possible (les e-mails de commande dépendent aussi de ce réglage) | Créer la boîte `no-reply@symoprint.com` (hPanel → E-mails), renseigner le bloc `smtp` de `_app/config.local.php`, compléter SPF/DKIM/DMARC (puis `p=quarantine`), tester avec un outil de délivrabilité **avant** d'ouvrir les inscriptions. *Propriétaire / hPanel / DNS* | **Code prêt — config externe à faire** |
| R-02 | Moyenne | Déni de service volumétrique, bots, scraping | Limites applicatives par IP/compte/session seulement ; CDN `hcdn` sans règles WAF connues | 429 + verrous, quotas | Activer un WAF/anti-bot (Cloudflare ou option Hostinger), Turnstile/hCaptcha sur inscription/contact/devis. *Config externe* | **À faire** |
| R-03 | Faible (était Élevée) | **Enrôlement MFA** : protégé par un **code d'activation** (personnel ou `mfa_setup_code`) ; reste à protéger ce secret | Le code de configuration est un secret statique tant qu'il est dans `config.local.php` | Code personnel haché et à usage unique pour les nouveaux membres ; refus + alerte e-mail sur mauvais code ; réinitialisation MFA par le super administrateur | Enrôler le compte administrateur existant, puis **retirer `mfa_setup_code`** de la configuration (les nouveaux membres utilisent leur code personnel) | **Corrigé dans le code — action propriétaire** |
| R-04 | Moyenne | Journal d'audit réécrivable par un attaquant maître de la base **et** de `app_key` | Même base que l'application | Chaînage HMAC ; **rétention 24 mois avec ancre** (la chaîne reste vérifiable) ; alertes e-mail sur les actions sensibles | Exporter le journal (CSV) régulièrement hors serveur ; sauvegarder `app_key` à part | À planifier |
| R-05 | Moyenne | **Fichiers malveillants** (PDF avec actions dans des flux compressés, formats AI/PSD/CDR/EPS exploitant une faille du logiciel qui les ouvre) | Pas d'antivirus sur l'hébergement mutualisé ; analyse **statique** limitée | Refus du contenu actif visible, ZIP inspecté, téléchargement forcé, aucun rendu côté serveur | Ouvrir les fichiers clients sur un poste à jour/isolé ; scanner (VirusTotal/AV poste) ; envisager un service d'analyse. *Process interne* | Accepté / à encadrer |
| R-06 | Faible | CSP : attributs `style=""` en ligne toujours tolérés (`style-src-attr 'unsafe-inline'`) | ≈ 100 attributs dans les vues | **Blocs `<style>` et feuilles externes interdits** (`style-src 'self'`) ; `script-src 'self'` strict ; `object-src 'none'` | Migrer les attributs vers des classes CSS puis retirer `style-src-attr` | Atténué |
| R-07 | Moyenne | Sauvegardes **sur le même compte d'hébergement** ; restauration MySQL **non testée** | Pas de stockage externe configuré ; outil testé sur SQLite | Cron quotidien, hors racine web, rétention 14 j | Copier périodiquement hors Hostinger ; **tester une restauration** dans une base temporaire (hPanel) | **À faire / à vérifier** |
| R-08 | Faible | `X-Powered-By: PHP/8.3.x` peut rester envoyé par le serveur | Retrait côté PHP et `.htaccess` (`Header unset`) | `header_remove` + règle `.htaccess` | Vérifier après déploiement ; sinon désactiver `expose_php` dans hPanel | **À vérifier en production** |
| R-09 | **Élevée** | **Secrets à renouveler** : mot de passe MySQL, jeton d'installation, mot de passe administrateur initial (apparus dans les échanges de mise en service) | Exposition passée | MFA + mot de passe à changer à la 1ʳᵉ connexion | Rotation selon `09` §5 ; stocker `app_key` hors serveur | **À faire (propriétaire)** |
| R-10 | Moyenne | **Fraude interne / paiements manuels** | Confirmation humaine par nature | Permission `payments`, référence obligatoire, journal, **alertes e-mail** sur remboursement, suppression, réglages, équipe, prix en masse | Revue hebdomadaire des paiements confirmés ; passerelle + webhooks signés plus tard ; les alertes exigent des e-mails délivrables (R-01) | Atténué |
| R-11 | Moyenne | **Conformité protection des données** (loi ivoirienne n° 2013-450, ARTCI), durées de conservation | Non évalué juridiquement ici | **Export JSON et suppression de compte en libre-service**, journal purgé à 24 mois, commandes conservées sans lien avec le compte | Revue juridique : durées de conservation comptable, déclaration à l'ARTCI, mise à jour de la politique de confidentialité (texte éditable dans Pages) | **Partiel — à vérifier (juridique)** |
| R-12 | Faible | Verrouillage ciblé d'un compte (déni de service) | Compromis anti-force brute | Verrou par couple compte+IP (5) ; verrou global par compte à 25 | Surveiller `login_blocked` | Accepté |
| R-13 | Info | Mots de passe déjà fuités | Appel externe (service de mots de passe compromis) | **Vérification k-anonymat implémentée**, échec ouvert, option `pwned_check` | Activer `'pwned_check' => true` dans la configuration (déjà prévu au déploiement) ; vérifier que l'hébergeur autorise la sortie HTTPS | **Corrigé dans le code — à activer** |
| R-14 | Faible | Fichiers de session par visiteur (disque) | PHP crée une session à chaque visite | GC probabiliste 1 %, répertoire privé | Surveiller l'espace | Accepté |
| R-15 | Faible | **Droits SQL** : l'utilisateur MySQL a tous les droits sur sa base (hébergement mutualisé, DDL nécessaire aux migrations) | Limite de l'offre | Base dédiée, **aucun accès distant** (vérifié), mot de passe fort | Créer un 2ᵉ utilisateur lecture/écriture sans DDL si l'offre le permet | À vérifier |
| R-16 | Info | HSTS sans `includeSubDomains`/`preload` | Décision à prendre | HSTS 1 an | Activer `includeSubDomains`+`preload` seulement si tous les sous-domaines sont en HTTPS | Décision propriétaire |
| R-17 | Faible | FPDF 1.9 embarqué sans canal de mise à jour | Bibliothèque unique | Surface limitée (PDF générés côté serveur, pas d'entrée de fichier) | Suivre les avis de sécurité FPDF | Accepté |
| R-18 | Faible | IP partagées (réseaux mobiles) : un verrou par IP peut gêner des utilisateurs légitimes | Compromis | Verrous par compte en plus de l'IP | Ajuster les seuils selon l'usage | Accepté |
| R-19 | Faible | Pas de supervision externe (disponibilité, alertes d'erreurs, copie des logs) | Non configuré | Journal d'audit + alertes e-mail critiques | Brancher un moniteur d'uptime et une copie des logs | À planifier |

## Ce que nous ne pouvons pas affirmer
- L'efficacité du CDN/WAF de l'hébergeur, la configuration TLS côté serveur (versions/chiffrements) au-delà du TLS 1.3 observé, la sécurité des autres comptes sur le même serveur.
- Le comportement exact sur MySQL du journal d'audit (transactions) et des migrations : validé sur SQLite, **à confirmer au premier déploiement**.
- L'absence de vulnérabilités non anticipées par nos tests.
